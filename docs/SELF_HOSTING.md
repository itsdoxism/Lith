# Luna self-hosting

Luna uses a staged bootstrap so the trusted base stays small and the self-host claim is executable rather than aspirational.

## Bootstrap chain

1. `compiler/lunac.py` compiles `compiler/lunac.luna` to Stage 1 C.
2. Stage 1 C is linked with `runtime/luna_runtime.c` to produce `lunac-stage1`.
3. `lunac-stage1` compiles `compiler/lunac.luna` to Stage 2 C.
4. Stage 2 is compiled and used to produce Stage 3 C.
5. Stage 3 is compiled and used to produce Stage 4 C.
6. The test requires Stage 2, Stage 3, and Stage 4 C output to be byte-for-byte identical.

The fixed point matters because Stage 2 and later are generated by the compiler written in Luna, not by the Python bootstrap implementation.

Run the proof with:

```sh
make selfhost
```

The same proof runs under `make test` and therefore under GitHub Actions CI.

## What is self-hosted today

`compiler/lunac.luna` contains its own lexer, token stream, precedence-based expression parser, statement parser, function-signature pass, and C emitter. It reads Luna source and writes generated C using only the small runtime surface in `runtime/`.

The current self-hosted compiler intentionally targets a bootstrap subset. This is enough for the compiler to compile itself, but it is not yet feature-identical to Stage 0. Stage-0-only features are tracked as parity work rather than being counted as part of the self-host proof.

## Trusted base

The bootstrap still trusts:

- the Python Stage-0 compiler for the first generation;
- a C11 compiler;
- the small C runtime used for file and string primitives.

After Stage 1 exists, subsequent compiler generations are produced by Luna itself.
